# PipelineIQ | Microsoft Entra ID OIDC sales integration lab

A complete Node.js application with a clickable, responsive sales CRM-style dashboard and Microsoft Entra OpenID Connect sign-in. **Sales records are sample data stored in the browser; this is not a multiuser CRM or production database.** No SCIM required.

## 1. Run locally (Windows PowerShell)

Extract the ZIP, open PowerShell in the folder containing `package.json`, and run:

```powershell
npm install
Copy-Item .env.example .env
notepad .env
```

Set `SESSION_SECRET` using the output of:

```powershell
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Keep `PORT=3000`, `APP_BASE_URL=http://localhost:3000` and enter `SESSION_SECRET` in `.env`. You may leave the three `ENTRA_*` values empty to preview first. Start:

```powershell
npm start
```

Open **http://localhost:3000/preview**. All nine dashboard sections work in preview mode without Entra setup. The application does not expose real identities or CRM records in preview.

## 2. Register PipelineIQ in Microsoft Entra ID

1. Open https://entra.microsoft.com and navigate to **Entra ID > App registrations > New registration**.
2. Name: **PipelineIQ - OIDC**.
3. Select **Accounts in this organizational directory only (single tenant)**.
4. Redirect URI platform: **Web**; URI: **http://localhost:3000/auth/callback**.
5. Click **Register**. Copy the **Application (client) ID** and **Directory (tenant) ID**.
6. Open **Certificates & secrets > Client secrets > New client secret**. Use a short lab expiry, save the **Value** securely; never share or upload it.
7. Update `.env`: `ENTRA_TENANT_ID`, `ENTRA_CLIENT_ID`, `ENTRA_CLIENT_SECRET`. Stop the running server with Ctrl+C and restart `npm start`.
8. Open **http://localhost:3000/auth/login**. After successful Microsoft sign-in, you land at `/dashboard`.

The application requests only OIDC `openid profile email` scopes. If your tenant requires consent, inspect the requested permissions before providing tenant-wide consent. Only a role authorized to grant consent should approve.

## 3. Restrict access to your existing Sales team

1. Go to **Entra ID > Enterprise applications > All applications > PipelineIQ - OIDC** (the service principal created from your app registration).
2. Open **Properties**; set **Assignment required? = Yes**; save.
3. Under **Users and groups > Add user/group**, select your **existing Sales security group**, then **Assign**. Requires appropriate Entra licensing for group assignment; use direct assignment if needed.
4. Test a regular member in an Edge InPrivate window: sign-in succeeds.
5. Test a regular unassigned user: sign-in should fail with `AADSTS50105`. Review **Sign-in logs** to confirm the evaluation. Group nesting is not supported for app assignment.

Note: Existing app sessions may remain valid after removing group access until they expire; this lab uses a 4-hour browser session and does not continuously re-check group membership.

## 4. GitHub and Render deployment

First inspect `.gitignore` to confirm `.env` is excluded:

```powershell
git init
git status --short --untracked-files=all
git add .
git diff --cached --name-only
git commit -m "Initial PipelineIQ OIDC sales dashboard"
git branch -M main
```

Create a **private** empty repository on GitHub named `PipelineIQ-Entra-OIDC` (no README, license or autogenerated `.gitignore`), then copy its real HTTPS URL and run:

```powershell
git remote add origin "PASTE_YOUR_GITHUB_HTTPS_URL"
git push -u origin main
```

For `remote origin already exists`, use `git remote set-url origin "ACTUAL_URL"`. For a private repo `repository not found`, check that Git is authenticated as the correct owner and Render/GitHub permissions are granted. **Never push `.env`**.

In Render: **New > Web Service** > connect the private repository. Use **Node**, branch `main`, build `npm install`, start `npm start`, and set `NODE_ENV=production`. Configure Environment Variables: `APP_BASE_URL` (the **exact** Render HTTPS URL), `SESSION_SECRET`, `ENTRA_TENANT_ID`, `ENTRA_CLIENT_ID`, and `ENTRA_CLIENT_SECRET`. Don't store secrets in GitHub. Render may supply its own `PORT`.

Entra **App registrations > PipelineIQ - OIDC > Authentication > Web**: add `https://YOUR-ACTUAL-RENDER-HOST.onrender.com/auth/callback`. Keep the localhost callback for local testing. Save, then test `https://YOUR-ACTUAL-RENDER-HOST.onrender.com/auth/login`.

**Note:** The Express MemoryStore is suitable only for testing. A production system needs durable sessions, a persistent CRM database, controls on data access, CSRF protection for any write APIs, operational logging, and session revocation. This lab's demo deals remain in each browser via localStorage.

## 5. Troubleshooting quick fixes

| Symptom | Check |
|---|---|
| `AADSTS50011` | The exact `/auth/callback` address must be registered under **Web** and match `APP_BASE_URL`. |
| `AADSTS50105` | User must be directly assigned or member of assigned Sales group; assignment required = Yes. |
| Need admin approval | Review OIDC permissions and your tenant consent policy; authorized admin may grant appropriate consent. |
| `AADSTS50126` | Invalid username/password; verify user cloud sign-in and hybrid password hash sync independently of PipelineIQ. |
| Incorrect client secret | Copy secret **Value** rather than Secret ID, verify expiry and Render environment variables. |
| Preview works, sign-in fails | Check three ENTRA_* values, redirect URI, app logs, and sign-in logs. |

## IAM engineer vs. app development

**IAM:** OIDC registration, redirect URI, credentials, assignment required, Sales group access, consent review, MFA/Conditional Access, sign-in investigation.

**App/DevOps lab:** UI build, source code, GitHub, hosting, demo pipeline data. **SCIM deliberately not configured**; it is not required for Entra to restrict new sign-ins to assigned Sales users.
